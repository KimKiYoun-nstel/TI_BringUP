# uart-manager 사용자 매뉴얼

## 현재 화면 구성

밝은 테마의 기본 창에서 페이지 스크롤 없이 연결 작업을 수행합니다.

1. **uartd 인스턴스 표**: 이름·접속 주소·수신 범위·COM·Baud·상태를 표시합니다. 행을 선택하면 아래 조작 대상이 바뀝니다.
   `서버 주소 등록`은 기존 서버의 주소록 추가, `등록 해제`는 주소록에서 제거입니다.
   `이 PC에 서버 실행`은 현재 PC에 새 uartd를 실행합니다. 인증 서버는 접속 비밀번호를 입력하고 `접속 확인`을 누릅니다.
2. **선택한 서버의 UART 장치**: 현재 실제 연결과 변경할 설정을 구분해 표시합니다.
   호스트 접속 성공 시 장치 목록을 자동 조회합니다. COM 번호와 장치 설명을 보고 선택하세요.
   `장치 연결`을 누르면 연결되고, 이후 버튼은 `연결 설정 적용`으로 바뀝니다.
   장치나 속도를 바꾸고 이 버튼을 눌러야 적용됩니다. 속도만 바꾸려면 `속도만 적용`을 사용합니다.
   Baud는 표준 속도를 목록에서 선택하거나 300~4000000 범위의 정수를 직접 입력합니다.
3. **UART 송수신 확인 / 서버 상세** 탭: 실시간 수신, 명령 전송과 PID·세션 정보를 제공합니다.
   데몬 설정/재시작 및 종료 버튼은 상단 인스턴스 표 아래에 있습니다.

## 실행 파일·배치·CLI

| 파일 | 역할 |
|---|---|
| `uartd.exe` | 실제 UART를 열고 TCP API·수신 로그를 제공하는 서버 |
| `uart-manager.exe` | 서버 주소록·인스턴스·COM/Baud 관리와 줄 단위 송수신 |
| `uartctl.exe` | 명령행 제어, raw `attach`, 읽기 전용 `watch` |

EXE에는 Python 런타임이 포함됩니다. USB-UART 드라이버는 장치 PC에 설치합니다.
배포의 `exe/` 폴더를 열고 아래 예제를 실행합니다. Python 실행 파일은 `python/`,
사용자 문서는 `manuals/`에 있습니다. Python 설치·실행 방법은 [Python 사용법](PYTHON_USAGE.md)을 참고하세요.
로컬 GUI의 서버 실행에는 옆의 `uartd.exe`가 필요합니다. 원격 접속 PC에는 Manager/CLI만 있어도 됩니다.
EXE 서버의 기본 로그는 실행 파일 옆 `logs/`, 소스 실행은 프로젝트의 `logs/`입니다.
`status.runtime_log`에서 실제 수신 로그 경로를 확인하고 쓰기 가능한 위치에서 실행하세요.

CLI는 주소만 입력해서 실행하는 프로그램이 아니며 하위 명령이 필수입니다.

```powershell
.\uartctl.exe --tcp 127.0.0.1:17001 status
.\uartctl.exe --tcp 127.0.0.1:17001 ports
.\uartctl.exe --tcp 127.0.0.1:17001 port COM7 --baud 115200
.\uartctl.exe --tcp 127.0.0.1:17001 attach
# 다른 터미널에서 사용 (읽기 전용)
.\uartctl.exe --tcp 127.0.0.1:17001 watch
```

`attach` 종료는 **Ctrl-] 다음 q**, `watch` 종료는 Ctrl+C입니다. CLI 전역 옵션은 하위 명령 앞에 둡니다.
인증 서버에는 아래 인증 예처럼 `--token-file` 또는 `UARTD_TOKEN`을 사용합니다.
기본 예제는 무인증 localhost 서버 기준이며 COM7은 예시입니다. 물리 장치 번호를 먼저 조회하세요.

## 구성과 용어

- **uartd**: 장치가 연결된 PC에서 COM을 열고 TCP API를 제공하는 프로세스.
- **호스트**: uartd가 실행되는 PC와 TCP 포트의 조합. 한 PC에 포트가 다른 여러 uartd를 실행할 수 있습니다.
- **Manager**: 사람이 API를 조작하는 화면. GUI 없이 Python/API/CLI/MCP로 같은 uartd를 제어할 수 있습니다.
- **호스트 등록**: GUI 주소록에 `HOST:PORT` 추가. 서버 설치·시작·장치 검색을 의미하지 않습니다.
- **인스턴스 이름**: 데몬/로그 식별 이름. IP 주소나 COM 이름이 아닙니다.

## 1. 이 PC에서 처음 사용

1. `exe/`의 `uart-manager.exe`와 `uartd.exe`를 같은 폴더에 둡니다.
2. Manager 실행 → **이 PC에 서버 실행**.
3. 서버 이름과 TCP 포트, 범위 **Local — 이 PC에서만 접속 (127.0.0.1)**을 정합니다.
   주소록에서 사용하지 않는 포트와 이름을 자동 제안합니다. 접속 비밀번호는 설정 시 4자 이상이며 Local에서 인증을 사용하지 않으면 비워 둡니다.
4. 확인하면 COM 없이 데몬을 시작하고 해당 행을 선택합니다. 이미 사용 중인 TCP 포트면 실행을 거절합니다.
5. **호스트 접속됨**이면 TCP 접속 성공입니다. **현재 연결: 장치 미연결**은 서버가 실행 중이지만 UART는 아직 열지 않았다는 뜻입니다.
6. 자동 조회된 목록에서 장치 선택 → Baud 확인 → **장치 연결**. 장치를 새로 꽂았다면 **장치 새로고침**을 누릅니다.
7. **현재 연결**의 COM과 Baud를 확인합니다. 실제 보드와 같은 Baud를 사용하세요.
8. **UART 송수신 확인** 탭에서 **Enter 전송**을 눌러 보드의 프롬프트를 확인합니다.
   **출력 ON**은 기본 켜짐입니다. 입력창에 명령을 쓰고 Enter 키 또는 **전송**을 누릅니다.

별도 콘솔 터미널을 함께 사용하려면 PowerShell에서:

```powershell
.\uartctl.exe --tcp 127.0.0.1:17001 attach
```

### UART가 실제로 응답하는지 확인하기

- **현재 연결**은 Windows가 COM을 열었다는 뜻입니다. 보드가 응답했다는 뜻은 아닙니다.
- **Enter 전송**은 입력창의 텍스트와 무관하게 CR(`0x0D`)만 보냅니다. 로그인 프롬프트/셸을 깨울 때 사용합니다.
- 명령 입력의 기본 줄끝은 **Enter (CR)**입니다. 장치에 맞게 CRLF / LF / 줄바꿈 없음을 선택할 수 있습니다.
- Enter를 누르면 입력창을 바로 비우고 다음 입력을 받습니다. **↑/↓**로 실행 중 입력 기록을 불러옵니다.
  송신 전용 TCP 연결을 재사용하고 순서대로 전송하므로 매번 전체 화면을 ‘요청 처리 중’으로 바꾸지 않습니다.
  UART 쓰기 확인과 보드 명령 실행 결과는 다릅니다. 응답은 수신 화면에서 확인합니다.
- **출력 ON/OFF**는 이 Manager의 실시간 수신 구독만 켜고 끕니다. OFF 중에도 입력·전송이 가능하며
  uartd의 UART 수신·로그 저장과 다른 Manager/CLI/에이전트의 작업은 계속됩니다.
  다시 ON으로 바꾸면 최근 20줄을 별도 표시한 뒤 새 데이터를 표시합니다. 더 이전 내용은 **최근 80줄 조회**로 확인합니다.
  OFF 상태에서도 최근 로그의 수동 조회는 가능합니다.
- 송신 실패 시 하단에 미확인 건수를 표시합니다. 일부는 이미 보드로 전달됐을 수 있어 자동 재전송하지 않습니다.
  서버 선택/비밀번호 변경/창 종료 시 이전 서버의 송신 대기열을 취소합니다. 입력 기록은 파일에 저장하지 않으며 서버를 바꾸면 비웁니다.
- **실수신 N자 · 시간**은 스트림 연결 후 실제로 새로 들어온 UART 문자 수와 마지막 수신 시각입니다.
  예전 로그는 별도 표식으로 표시하며 새 수신 횟수에 포함하지 않습니다. **화면 지우기**는 표시와 계수만 초기화합니다.
- **최근 80줄 조회**는 이전 로그를 추가 표시합니다. 라이브 수신과 구분하세요.
- 이 화면은 줄 단위 송수신 확인용입니다. 전체 ANSI 화면 제어, raw 키보드 조작이 필요한 프로그램은 `uartctl attach`를 사용하세요.
- 보드가 켜져 있어도 로그인/셸에서 입력을 기다리면 새 출력이 없을 수 있습니다.
  Enter에 응답이 없으면 다른 COM 채널, Baud, 보드 UART 배선·부팅 상태를 확인합니다.

### COM·Baud를 바꾸면 attach를 다시 해야 하나요?

**필요 없습니다.** 같은 uartd에서 COM 교체·속도 변경·COM 해제/재연결을 해도 기존 attach TCP 연결은 유지됩니다.
COM 변경 확인창에서 승인하면 접속 중인 모든 클라이언트의 UART 대상이 함께 바뀝니다.
전환 순간의 데이터 손실 가능성은 있으며, 보드가 자동 로그인되거나 재부팅되는 것은 아닙니다.
uartd 프로세스 자체를 종료/재시작하거나 TCP 연결이 끊기면 attach를 다시 실행해야 합니다.

COM 번호는 PC와 USB 연결에 따라 달라집니다. 장치 목록을 조회하고 실제 보드 응답을 확인하세요.

## 2. 호스트 등록 / 선택 / 삭제

**서버 주소 등록** → `127.0.0.1:17001` 또는 `192.168.0.170:17001` 입력. 서버를 새로 실행하는 기능이 아닙니다.
URL 경로나 COM 이름은 입력하지 않습니다. IPv4/호스트 이름을 지원하고 IPv6 주소는 현재 지원하지 않습니다.
등록한 전체 인스턴스의 상태를 약 3.5초마다 백그라운드 조회합니다. 실패한 서버도 행별로 표시하며 다른 서버 조회는 계속합니다. 자동 조회는 버튼을 잠그거나 상태바 메시지를 교체하지 않습니다. 포트 목록은 **선택한 호스트 PC**의 장치 목록입니다.

### Manager 설정 저장과 재실행

Manager는 Qt QSettings를 사용해 **Windows 레지스트리**의 현재 사용자 영역
`HKEY_CURRENT_USER\Software\uartTool\uart-manager`에 자동 저장합니다.
`endpoints`는 주소 목록, `local_profiles`는 이름·바인딩·포트·PID와 선택적 COM/Baud 관리 이력입니다.
Python 소스로 실행해도 같은 동작이며, EXE 내부나 EXE 옆 파일에 저장하는 방식이 아닙니다.
별도 저장 동의 화면이나 관리자 권한 요청은 없습니다. 일반 사용자 권한의 HKCU 쓰기로 동작합니다.
EXE를 이동/삭제해도 설정은 남고, 같은 PC·같은 Windows 사용자로 실행하면 다시 불러옵니다.
다른 PC/사용자는 처음에 서버 주소를 직접 등록해야 합니다. 자동 서버 검색은 제공하지 않습니다.
비밀번호는 실행 중 메모리에서 서버별로 기억하므로 행을 바꿀 때 다시 입력하지 않아도 됩니다. 파일/레지스트리에 저장하지 않으며 Manager를 다시 열면 재입력합니다.
**등록 해제**는 주소록 항목만 지우며, 데몬을 종료하지 않습니다. 마지막 항목 하나는 유지합니다.

### 여러 로컬 인스턴스 관리와 재시작

각 uartd는 독립적인 **TCP 수신 주소/포트 + UART 장치 + Baud**를 가집니다.
예: board-a `127.0.0.1:17001 → COM11 / 115200`, board-b `127.0.0.1:17002 → COM10 / 9600`.
한 행을 선택해 장치 연결/변경, 속도 변경, 로그 조회, 종료를 수행하면 그 서버만 대상이 됩니다.

- **서버 설정 / 재시작**: Manager에서 실행한 로컬 서버의 이름, Local/External, TCP 포트, 비밀번호를 변경합니다.
  현재 연결된 COM/Baud를 읽고 선택 서버를 종료한 뒤 변경한 설정으로 실행합니다. 클라이언트는 새 주소/비밀번호로 재접속해야 합니다.
- 새 TCP 포트의 충돌은 종료 전에 검사합니다. 새 설정의 실행 실패 시 기존 설정 복구를 시도하며 결과를 상태바에 표시합니다.
- TCP 포트가 바뀌면 표의 기존 주소를 새 주소로 교체합니다. 다른 인스턴스는 유지됩니다.
- Manager에서 **선택한 uartd 종료**로 정지한 로컬 인스턴스도 같은 설정/재시작 버튼으로 다시 실행할 수 있습니다.
- 로컬 실행 이력(이름·수신 범위·포트·PID, 명시적 종료 시 COM/Baud)은 QSettings에 보관합니다.
  Manager 재실행 후에도 이력은 유지되지만 비밀번호는 재입력합니다. 실행 중 프로세스의 PID/이름이 다르면 임의로 종료하지 않습니다.
- 주소만 등록한 기존 서버와 원격 서버는 COM/Baud/로그/종료를 관리합니다. 로컬 실행 이력이 없는 서버의 프로세스 재시작은 해당 PC에서 수행합니다.

## 3. 다른 PC에서 접속: 무엇이 필수인가?

| 설정 | 의미 / 필수 조건 |
|---|---|
| `127.0.0.1` 바인딩 | 동일 PC에서만 접속. 기본적으로 토큰 불필요. 토큰을 설정했다면 로컬도 인증 필요 |
| `0.0.0.0` 바인딩 | 모든 IPv4 인터페이스에서 수신. 데몬은 토큰 설정 필수 |
| 접속 주소 | 서버 PC의 실제 IP 또는 DNS 이름 + TCP 포트. `0.0.0.0`으로 등록하지 않음 |
| 인증 토큰 파일 | 서버 시작 시 읽는 UTF-8 텍스트 파일. 공백 제거 후 4자 이상 공유 비밀 문자열 |
| GUI 접속 비밀번호 | 서버 실행 시 설정한 문자열. 입력 후 Enter 또는 접속 확인. 프로토콜의 token과 같은 값 |
| 네트워크 | 서버까지 경로와 TCP 포트 접근 필요. Windows 방화벽 인바운드 허용은 필요한 원격 IP로 제한 |

GUI 없이 비밀번호를 지정하려면 서버 PC의 EXE 폴더에서:

```powershell
$env:UARTD_TOKEN = "YOUR_SHARED_PASSWORD"
.\uartd.exe start --no-serial --no-unix-socket --instance-id board-a --tcp 0.0.0.0:17001
```

GUI에서는 **External — 외부 PC 접속 허용 (0.0.0.0)**을 선택하고 **접속 비밀번호를 직접 입력**합니다.
GUI에 파일 선택은 필요 없습니다. 비밀번호는 자식 프로세스 환경변수 `UARTD_TOKEN`으로 전달하며
명령줄 인자·파일·주소록에는 저장하지 않습니다. 서버를 새로 실행할 때 다시 입력합니다.
원격 PC에서 서버의 실제 IP:포트를 등록하고 같은 비밀번호를 입력합니다.
토큰은 계정/사용자별 권한 체계가 아닌 **공유 비밀**입니다. 인증된 클라이언트는 종료·COM 변경·송신도 가능합니다.
TCP 자체에는 TLS가 없습니다. 신뢰 LAN 또는 VPN/SSH 터널을 사용합니다.
설정한 비밀번호는 Local에서도 4자 이상이어야 합니다. Local에서 비우면 인증 없이 실행합니다.
인증된 클라이언트의 사용자별 읽기/쓰기 권한이나 감사 계정 체계는 없습니다.
비밀번호 파일과 로그는 Git/배포에 포함하지 않으며 접근 권한·보존 기간을 관리하세요.
Windows 방화벽 인바운드는 필요한 IP/서브넷·TCP 포트만 허용합니다. 관리자 PowerShell 예:

```powershell
New-NetFirewallRule -DisplayName 'uartd TCP 17001' -Direction Inbound -Protocol TCP -LocalPort 17001 -RemoteAddress 192.168.0.0/24 -Action Allow
```

SSH 서버를 별도로 운영한다면 `ssh -N -L 17002:127.0.0.1:17001 user@SERVER` 후
로컬 GUI에 `127.0.0.1:17002`를 등록할 수 있습니다(서버 uartd는 loopback 바인딩 가능).

CLI 인증 예:

```powershell
.\uartctl.exe --tcp 192.168.0.170:17001 --token-file .\client.token status
```

`client.token` 내용은 서버 토큰과 동일해야 합니다. 데몬/CLI는 `UARTD_TOKEN` 환경 변수도 지원합니다.
토큰 파일을 바꿨다면 데몬을 재시작해야 반영됩니다.

### 원격 Manager, CLI, 에이전트를 함께 사용하기

다른 PC에도 `uart-manager.exe`를 두고 **서버 주소 등록 → 서버 PC의 IP:포트 → 접속 비밀번호 → 접속 확인** 순서로 연결합니다.
클라이언트 PC에는 USB-UART 연결이나 로컬 uartd가 필요 없습니다. COM 목록과 설정은 서버 PC의 것입니다.
동일 PC와 원격 PC의 Manager를 동시에 열어 수신할 수도 있습니다.

Manager의 송수신 탭과 `uartctl attach`는 같은 UART를 공유합니다. Manager는 간단한 줄 입력·수신 모니터와 서버 관리용이고,
`attach`는 키 입력을 즉시 전달하는 raw 터미널용입니다. 탭은 완전한 ANSI 터미널 에뮬레이터가 아닙니다.

에이전트는 `uartctl.py`, Python API 또는 `uart_mcp.py`를 통해 같은 TCP 서버를 이용합니다.
Manager에서 출력 ON이면 에이전트 작업 중 발생한 **보드의 UART 수신 데이터**도 실시간으로 보입니다.
다른 클라이언트가 보낸 TX 바이트 자체나 MCP 도구 호출 내역을 복제하는 기능은 아닙니다.
보드가 명령을 에코하면 입력 명령도 보이고, 에코하지 않으면 응답만 보입니다. 여러 클라이언트가 동시에 쓰면 입력이 섞일 수 있습니다.

## 4. 상태와 작업의 영향

| 항목 / 버튼 | 의미 |
|---|---|
| UART 상태 | `connected`: 장치 열림, `disconnected`: 미연결, `error`: 장치 오류 |
| RW / RO | 터미널 쓰기 가능 / 읽기 전용 접속자 수 |
| 세션 번호 | UART 연결 세대. COM 변경 시 수신 검색 버퍼가 초기화됨 |
| 장치 연결 / 연결 설정 적용 | 전체 사용자에게 적용. RW 사용자가 있으면 확인 후 force 요청 |
| 속도만 적용 | 현재 UART 속도 변경. 보드 설정과 일치해야 함 |
| COM 연결 해제 | UART만 닫음. uartd/TCP 접속 유지 |
| 선택한 uartd 종료 | 데몬 자체 종료, 모든 접속 종료. 원격 API로 다시 시작할 수 없음 |
| 창 닫기 | Manager만 종료. 데몬은 계속 실행 |

`uartd start`는 백그라운드 프로세스로 실행하고 돌아옵니다. `run`은 포그라운드 실행입니다.
Windows 서비스나 부팅 자동 시작은 등록하지 않습니다. 종료된 원격 서버의 재시작은 해당 호스트에서 수행합니다.

진행 중인 expect/command 또는 미완료 송신이 있으면 강제 COM 변경도 거부됩니다. 작업 완료 후 다시 시도합니다.
새 COM 열기 실패 시 기존 COM은 유지됩니다. 여러 송신자는 같은 UART를 공유하므로 에이전트 명령은 직렬화하세요.

### 2026-11-05 안정성 개선 동작

- 개선 EXE 배포 위치는 `packages/exe/`입니다. 재빌드만으로 실행 중인 프로세스가 바뀌지는 않으므로 전환 시 기존 서버·Manager를 종료한 후 새 파일을 실행합니다.
- `command`/`send_expect`는 기본 독점 송신 보호를 적용합니다. 다른 송신이나 RW attach가 있으면
  busy로 거부될 수 있습니다. 기존 RW attach를 종료하거나 `watch`로 읽기 전용 접속하세요.
  명령 완료/timeout 후 보호가 해제됩니다. 공유 쓰기가 필요한 API 호출만 `exclusive=false`를 명시합니다.
- 출력 ON 시 최근 20줄을 별도 backlog로 표시합니다(현재 로그 마지막 48KiB 내).
  신규 수신 카운터에는 포함하지 않습니다. 수신 화면은 40ms 배치·262,144문자/2,000블록 제한이며,
  대기 큐 초과 시 최신 내용을 유지하고 생략량을 표시합니다. 원본 수신 로그와 UI 표시량은 다를 수 있습니다.
- 수신/데몬 로그는 각각 10MiB + 백업 3개로 회전합니다. tail은 현재 파일 마지막 48KiB만 조회하며,
  큰 command 결과도 최신 부분만 반환할 수 있으므로 자동화는 API의 잘림 표시를 확인하세요.
- CLI 일반 응답은 기본 10초 제한이며 `--response-timeout 20`처럼 변경합니다.
  stream은 handshake 성공 후 계속 기다립니다. 송신 실패를 자동 재전송하지 않습니다.

## 5. 문제 해결

- `unauthorized`: 선택한 서버의 **접속 비밀번호**를 입력하고 Enter 또는 **접속 확인**을 누릅니다. GUI를 다시 열면 비밀번호를 다시 입력해야 합니다.
- 연결 거부: uartd가 실행 중인지, 포트·바인딩이 맞는지 확인. 호스트 등록만으로는 시작되지 않음.
- 연결 시간 초과: IP, 방화벽, VPN/네트워크 경로 확인.
- COM 목록이 비어 있음: 선택한 서버 PC에 USB-UART와 드라이버가 있는지 확인.
- COM 목록 조회 실패: 서버가 실행 중인지 확인하고 비밀번호 입력 후 **장치 새로고침**을 누릅니다. 실패한 목록 조회는 다음 상태 갱신 때 다시 시도합니다. 목록 조회 오류가 UART 연결 상태를 초기화하지는 않습니다.
- COM 열기 실패: 다른 터미널이 장치를 점유하는지, 장치 번호가 바뀌었는지 확인.
- 작은 창/높은 배율: 연결 설정은 기본 화면에서 확인하고, 상세 정보는 `서버 상세` 탭을 선택합니다.
- 버튼 비활성화: 사용자 요청 처리 중 잠시 비활성화. 자동 상태 조회에서는 비활성화하지 않음. 속도 적용·연결 해제는 UART가 연결되어야 활성화됨.

Windows에서 Manager의 서버 실행·재시작은 콘솔 창을 표시하지 않습니다. uartd는 별도 백그라운드 프로세스로 계속 동작하며 실행 출력은 Manager의 상태 표시와 `logs` 폴더에서 확인합니다.
